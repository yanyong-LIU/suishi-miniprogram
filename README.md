# 碎事清单 · 微信小程序

一个「选好日期时间、到点叫你」的待办清单。原生小程序实现（WXML / WXSS / JS / JSON），
无第三方 UI 库、无 npm 依赖，整个目录可直接导入微信开发者工具运行。

本工程是《碎事清单-可体验原型.html》的逐项改写：页面结构、交互路径、文案措辞、
视觉令牌与原型一致；农历引擎与重复规则引擎是从原型搬运后逐日对拍验证过的。

## 三、提醒是怎么送达的

小程序没有后台常驻能力，也没有本地定时通知 —— 这是「到点提醒」类小程序最容易
被做错的地方：看起来开了提醒，其实一条也发不出去。本工程用两条通道：

**主通道｜云函数定时触发器 → 订阅消息**
`remind-tick` 每分钟扫一次 `suishi_reminders`，到点的调 `subscribeMessage.send`。
不依赖用户是否开着小程序。

**兜底通道｜写入手机系统日历**
`wx.addPhoneRepeatCalendar`，闹钟由系统负责，完全不依赖微信。
微信只提供 day / week / month / year 四种周期，所以**每季**与**农历每年**只能写最近一次
（写 `month` 会被当成「每月」，错得更远）；保存时用 toast 说明，不让用户误以为整条规律都进去了。
`.ics` 导出则不同：每季可用 `FREQ=MONTHLY;INTERVAL=3` 完整表达，只有农历每年退化为单次。

### 关于「剩 N 次」

微信规定「用户授权一次 = 只能下发一条」。所以界面上那个剩余次数是真实的条数，
不是装饰。用户勾选「总是保持以上选择」后额度会静默累积，服务端在
`suishi_users.quota` 里维护，界面三处读数（详情页 / 我的页 / 授权弹层）同源。

额度上限 `QUOTA_CAP = 15`；低于 `QUOTA_LOW = 3` 时变琥珀色；用尽后变朱砂色
并在保存时主动引导补一次授权。

### 隐私边界（有意为之的取舍）

任务标题、备注、完成记录**一律不上传**。云端只存「提醒时间 + 随机 deviceId」，
所以订阅消息的文案只能是通用句（「你有碎事到点了 / 打开小程序看看是哪一件」），
做不到「提醒：交水费」。想看清楚哪一件，点进来就知道 —— 这是隐私与文案之间的
取舍，不是功能缺失。

## 四、验证方式

四项校验脚本（在 `../checks/`，可随时复跑）：

```
node ../checks/run-all.mjs
```

1. **静态审计** —— WXML 表达式里有没有写方法调用、`usingComponents` 指向的组件
   是否都存在、页面四件套是否齐全、事件绑定的处理函数是否都定义了、
   样式类是**在该文件真实可达的样式作用域**里存在（会解析 `@import`），
   用到的图标组合是否都有对应规则
2. **保真度比对** —— 与原型逐属性核对：原型 `px × 2` 必须等于 `rpx`，
   小程序不该出现原型里没有的色值。刻意的偏离登记在脚本的 `EXEMPT` 表里
3. **引擎对拍** —— 小程序端的农历与重复规则引擎 ↔ 原型核心，逐日比对
4. **运行时冒烟** —— 用 Node 端的 `wx` 桩实例化全部 10 个页面与 12 个组件，
   真实调用每一个事件处理函数（含弹层 Promise 回程），捕获异常

当前状态：四项全部通过，明细见 `../checks/README.md`。

## 五、行为约定（改代码前值得先看一眼）

- **重复任务完成是「原位推进」**：行不跳位，只换时间与计数，同时落一条历史记录
- **删除分三档**：仅删除这一次 / 删除此次及以后 / 删除全部
- **最近删除保留 7 天**（`TRASH_DAYS`），过期由 `sweepTrash()` 清理
- **超过 1 小时未发出的提醒**（`RETRY_MS`）标记为「提醒未发出」且不再补发 ——
  补发一条三小时前的提醒只会造成困惑
- **边界退化**：每月 31 日遇 2 月取当月末日；每季按 3 个月推、锚在创建月，
  31 日锚 5 月时依次落 8/31 → 11/30 → 次年 2/28 → 5/31；每年 2/29 遇平年取 2/28；
  农历闰月不存在时退化为常月同日；腊月三十遇小月取廿九。所有退化都会在
  重复规则页给出琥珀色提示，不静默处理
- **状态单例**：小程序模块缓存天然单例，页面一律通过 `utils/store.js` 读写，
  变更用 `subscribe/emit` 通知，不要在页面里各存一份
